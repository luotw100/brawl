# 文字脚本审稿

按以下顺序审阅成稿和所引原文，边发现边修改。每条意见指出具体段落、问题原因和可执行的修改。没有成片时只评估脚本，不假称已听音频或观看影片。

## 1. 事实与引用

- 每段原话是否来自最终生效正文；是否误取了后来作废的回复，或把广播与原答重复播放？
- 选段是否保留限定语、否定词、时间条件和指代前提？多次发言是否被拼成了玩家从未说过的新立场？
- 票型、队伍、任务牌总数、得分、查验与胜负是否对到本局事件？不把终局状态当成早期局面。
- 规则约束是否来自本局规则？坏人可交成功牌，零失败不能证明全队好人；第4任务的一张失败仍说明队内有坏人，即使任务成功。
- 查验真实结果与玩家公开声明是否分清？合法谎言不能被编导“纠正”掉。
- 旁白是否把玩家策略假设写成规则证明，把玩家自述写成已证实动机，或把一次表现扩大成模型稳定能力？

关键事实有冲突且查阅原记录仍不能解决，标为待核实，缩小或移除相关结论。不要替原比赛补一次行动或重新结算来美化故事。

## 2. 信息揭示与时间顺序

- 按成片顺序检查观众每时刻能知道的内容，是否有身份、任务牌归属、真实查验结果或终局结论提前泄露？
- 将检查扩展到身份色、角色图标、标题、画外音、字幕与预告，不只读旁白。
- 提前片段与回放是否标明时间？有没有把后来的反应放到早先发言后，制造实际不存在的回应关系？
- 公开信息足以推出的结论可以呈现，但不把“观众现在看懂”改写成“所有玩家当时都已明白”。
- 秘密揭示是否解决了此前提出的问题，并且有足够铺垫？全部拖到末尾、与主线无关地翻身份也可能影响理解。

默认逐步揭晓不要求人为遮住已经公开的事实，也不要求把所有秘密憋到终局。揭示位置由主线决定，并记入计划。

## 3. 故事是否成立

- 开头是否提出本局具体、真实的问题？标题承诺能否由实际素材兑现？
- 每段是否推进冲突、提供证据、加深人物选择或完成回应？若删去一段不影响理解或体验，应考虑压缩。
- 重要结论是否有此前可见的证据？反转是素材自身产生的，还是删掉前提后人为制造的？
- 是否为了平均分配镜头而保留弱段，或为了固定主角而忽略决定局势的人？
- 结尾是否交代真实胜负并回应核心问题？好人三次任务成功与最终获胜不能混淆。
- 玩家原话是否仍在推动剧情？旁白过多时，优先找能直接承载冲突或判断的真实发言。

给出至少一个确实有效的段落及原因，保留它在修改中的功能。不要为符合模板凭空添加支线或情绪。

## 4. 观众是否跟得上

- 每段进入时是否交代必要局面：现在是哪次任务、当前队伍与比分、争议是什么？不要每段重复完整规则。
- 被提及的席位与证据能否在画面找到？复杂牌数推理是否拆成可逐步阅读的画面？
- 指代、回忆与跳剪是否需要补一句中性连接？省略的先前发言是否正是后续判断的前提？
- 旁白是否增加上下文或意义，还是逐字朗读已经显示的表格？需要阅读的画面能否适当留白？
- 是否要求制作不存在的真实表情、停顿或镜头？改成可执行的图形或标明为新制作的表现手法。

## 5. 节奏、时长与交付

- 时长是否来自实际口播文字与独占画面时间？并行部分有没有重复计时？是否把字数预算冒充真实音频长度？
- 重复赞成、重复自证与流程通知是否挤占了冲突和结果？快段与关键推理段是否有区别？
- 超预算时优先合并重复信息和删弱支线，保留证据链；不足预算不添加无来源的剧情凑时长。
- 段落与声音块 ID、输入指纹、选材引用、揭示计划和最终文字是否相互一致？
- 所有计划中的音频、画面和字幕时间是否明确为待制作/估算？是否列明后续需要配音校时和真实审片？

结论使用“文字审稿完成，待配音校时”“需修改”或“来源不足”。只有实际完成的检查才能记为通过。格式通过与事实通过、脚本可读与成片好看分别报告。
